# spec.md —— 辅导员训练平台 需求规范

> 本文档是项目的**唯一需求来源（真理之源）**，只描述「做什么（WHAT）与为什么（WHY）」，**不涉及任何技术实现**。所有功能需求、业务规则、角色权限、验收标准均以本文为准。若与其它文档冲突，以本文为准。
>
> 需求编号约定：**FR** = 功能需求（Functional Requirement）；**BR** = 业务规则（Business Rule）；**NFR** = 非功能需求；**AC** = 验收标准（Acceptance Criteria）。

---

## 1. 项目概述

### 1.1 系统目标

搭建**辅导员训练平台**，面向高校辅导员队伍的专业能力培养与考核。

### 1.2 业务目标

支撑辅导员「日常学习 → 模拟演练 → 正式比赛」全流程，实现**以赛促学、以练促能**。

### 1.3 范围边界

本平台覆盖：题库管理、正式比赛、日常练习、成绩查询、现场比赛、比赛练习六大功能模块。用户认证、权限控制为支撑性能力。

**明确不在范围内（Out of Scope）**：
- 移动端 App；
- 第三方单点登录（SSO）对接；
- 消息推送/短信/邮件通知（本期不做）；
- 面试环节的视频通话/直播能力（面试环节按题目与评分处理，不包含实时音视频）。

## 2. 术语表（Glossary，全文统一，无歧义）

| 术语 | 定义 |
| --- | --- |
| **题目（Question）** | 考核的最小单元，含题干、选项、标准答案、分值、题型、所属题库。 |
| **客观题** | 题型为「单选 / 多选 / 判断」的题目，由系统按标准答案自动判分。 |
| **主观题** | 题型为「主观题」的题目，由业务管理人员人工评分，系统不自动判分。 |
| **题库（Question Bank）** | 题目的归属容器，分为「自建题库」与「共享题库」。 |
| **自建题库** | 共享标记 shared = false，由业务管理人员增删改查。 |
| **共享题库** | 共享标记 shared = true，对所有登录用户**只读**（不可新增/编辑/删除）。 |
| **试卷（Paper）** | 一次考核/练习所用的题目集合快照，含生成方式（随机/固定）与总分。 |
| **随机试卷** | 按题型、数量、分值规则从指定题库随机抽取题目并快照成试卷。 |
| **固定试卷** | 由业务管理人员手动逐题挑选并固定顺序组成试卷。 |
| **比赛（Competition）** | 正式比赛实例，含名称、内容、组织人、参赛人员与若干环节。 |
| **环节（Stage）** | 比赛的组成单元，类型为「笔试环节」或「面试环节」，按顺序编号。 |
| **笔试环节** | 含客观题与主观题，客观题自动判分、主观题人工评分。 |
| **面试环节** | 仅含主观题（面试题），由评委/组织方人工评分，无客观题。 |
| **练习批次（Practice Batch）** | 日常练习的实例，含批次名称、时间范围、参与人员、试卷与模式。 |
| **学情辨析** | 辅导员基于学生照片/姓名等基础信息，辨析学生学情（学业、心理、困难等）并作答的题型/环节。 |
| **客观分** | 客观题系统判分累计得分。 |
| **主观分** | 主观题人工评分累计得分。 |
| **基础知识成绩** | 客观分 + 主观分。 |
| **阶段成绩** | 某个比赛环节内全部题目得分之和。 |
| **总成绩** | 比赛中全部环节阶段成绩之和。 |
| **排名** | 按总成绩降序排列得到的名次。 |
| **现场比赛** | 由现场组织者主持的线下比赛辅助，含学情辨析、案例分析（分组）、谈心谈话三类。 |

## 3. 角色定义

| 角色代码 | 角色名称 | 职责 | 约束 |
| --- | --- | --- | --- |
| ADMIN | 业务管理人员 | 题库管理、正式比赛、日常练习、成绩查询 | 可查询全部成绩 |
| ORGANIZER | 现场组织者 | 现场比赛 | 仅负责现场比赛组织与展示 |
| COUNSELOR | 辅导员 | 比赛练习、成绩查询 | 只能查询**本人**成绩 |
| DEPT_HEAD | 院系学工负责人 | 成绩查询 | 只能查询**本院系辅导员**成绩 |

> 角色为闭集，全文统一，不得新增或改名。一个用户有且仅有一个角色。

## 4. 功能需求

### 4.1 模块一：题库管理（question-bank）

**FR-QB-1 题库管理**：业务管理人员可创建题库，题库字段包括：题库名称、所属人、是否共享（shared）。

**FR-QB-2 题目增删改查**：业务管理人员可对**自建题库**中的题目执行增、删、改、查；对**共享题库**中的题目仅可查看（只读）。

**FR-QB-3 题目字段**：题目包含以下字段：
- 题干（必填）
- 题型（必填，枚举：单选/多选/判断/主观题）
- 选项（客观题必填，为选项对象列表，每项含 key 与 text；判断题固定为「正确/错误」两选项；主观题无选项）
- 标准答案（客观题必填：单选/多选记录正确选项的 key 集合；判断题记录 TRUE 或 FALSE；主观题记录参考答案文本）
- 分值（必填，正整数，单位「分」）
- 难度（必填，枚举：简单/中等/困难）
- 所属题库（必填）
- 是否共享（随所属题库决定，题目自身不单独设置共享标记）

**FR-QB-4 生成试卷**：业务管理人员可生成试卷，生成方式为：
- **随机试卷**：指定来源题库、题型、数量、每道题分值，系统从题库中随机抽取指定数量题目，**生成时快照题目内容与顺序**。
- **固定试卷**：手动挑选题目并固定顺序。

**FR-QB-5 删除题目前置条件（BR-QB-1）**：题目**只有同时满足以下两个条件才允许删除**：
1. 该题目**未被任何试卷使用**（试卷快照中不引用该题）；
2. 该题目**不在共享题库中**（即其所属题库 shared = false）。

> 任一条件不满足，删除操作被拒绝并返回明确错误提示。共享题库中的题目不可删除；已被试卷引用的题目不可删除。

**FR-QB-6 共享题库只读**：共享题库对所有登录用户只读；任何角色（含 ADMIN）都不得对共享题库中的题目进行新增/编辑/删除，也不得修改共享题库的共享标记。

### 4.2 模块二：正式比赛（competition）

**FR-COMP-1 创建比赛**：业务管理人员可新增比赛，字段包括：比赛名称（必填）、内容（比赛说明，必填）、组织人（必填，取当前 ADMIN）、参赛人员（必填，从辅导员中多选）、环节配置。

**FR-COMP-2 环节设置**：比赛由若干**环节**组成，环节类型为「笔试环节」或「面试环节」。
- **默认配置**：笔试 2 个环节 + 面试 3 个环节（共 5 个环节）。
- 业务管理人员可在默认基础上**新增/删除/调整顺序**环节。
- 每个环节包含：环节名称、环节类型、环节顺序号（从 1 递增）、关联试卷（笔试环节必填试卷；面试环节关联面试题组）。

**FR-COMP-3 比赛状态**：比赛具有状态，枚举：未开始（NOT_STARTED）/ 进行中（IN_PROGRESS）/ 已结束（FINISHED）。状态由业务管理人员操作流转：未开始 → 进行中 → 已结束。

**FR-COMP-4 参赛人员管理**：业务管理人员可为比赛增删参赛辅导员；比赛开始后仍可调整参赛人员，但已产生的成绩保留。

**FR-COMP-5 环节成绩**：每个环节结束后产生**阶段成绩**；比赛所有环节的阶段成绩之和为**总成绩**（详见模块四）。

### 4.3 模块三：日常练习（practice）

**FR-PRAC-1 练习批次**：业务管理人员可创建练习批次，字段包括：批次名称（必填）、时间范围（开始时间、结束时间，必填）、参与人员（必填，从辅导员中多选）、试卷（必填）。

**FR-PRAC-2 练习模式**：练习批次的模式为「练习模式」，答题规则为**答一题、提交后立即查看该题答案**，可继续下一题。

**FR-PRAC-3 模拟模式**：练习批次的模式为「模拟模式」，包含两类：
- **模拟批次**：答题规则为**全部作答完成后一次性提交，提交后才能查看答案**。
- **学情辨析批次**：内容为学情辨析题（学生照片/姓名辨析），答题规则同模拟批次（全部答完才能看答案）。

**FR-PRAC-4 批次状态**：练习批次具有时间有效性，仅在 开始时间 ≤ 当前时间 ≤ 结束时间 内可作答。

### 4.4 模块四：成绩查询（score）

**FR-SCORE-1 基础知识成绩计算（BR-SCORE-1）**：基础知识成绩 = 客观分 + 主观分。

**FR-SCORE-2 客观分自动判分（BR-SCORE-2）**：
- 单选题：所选选项与标准答案一致得该题满分，否则 0 分。
- 判断题：所选判断与标准答案一致得该题满分，否则 0 分。
- 多选题：所选选项集合与标准答案选项集合**完全一致**得该题满分，否则 0 分（不设部分分，消除歧义）。

**FR-SCORE-3 主观分人工评分（BR-SCORE-3）**：主观题由业务管理人员人工评分，分值范围为 [0, 该题分值] 的整数。未评分的主观题主观分记为 null（待评分），不计入成绩，并在成绩列表标记「待评分」。

**FR-SCORE-4 阶段成绩（BR-SCORE-4）**：阶段成绩 = 该环节内全部题目得分之和（笔试环节 = 客观分 + 主观分；面试环节 = 主观分合计）。

**FR-SCORE-5 总成绩（BR-SCORE-5）**：总成绩 = 该比赛全部环节阶段成绩之和。

**FR-SCORE-6 排名（BR-SCORE-6）**：同一比赛内按总成绩**降序**排名；总成绩相同时按参赛人员**姓名拼音升序**作为稳定次序（并列名次连续编号：如 1、2、2、4）。

**FR-SCORE-7 成绩查询范围**：按 §3.1 权限矩阵控制：ADMIN 查全量、COUNSELOR 查本人、DEPT_HEAD 查本院系辅导员。

**FR-SCORE-8 导入主观成绩**：业务管理人员可将主观成绩通过文件（CSV/XLSX）批量导入。导入字段：参赛人员标识、题目标识、主观分。导入规则：覆盖式更新对应主观题的 subjective_score；越界分数（小于 0 或大于该题分值）的行被拒绝并逐行反馈。

**FR-SCORE-9 导出主观成绩**：业务管理人员可导出主观成绩为文件（CSV/XLSX），导出字段：比赛/批次、环节、参赛人员、题目、主观分、评分状态。

**FR-SCORE-10 练习成绩**：日常练习（练习/模拟/学情辨析批次）产生的成绩独立记录，**不参与**正式比赛排名（BR-SCORE-7）。

### 4.5 模块五：现场比赛（live-match）

**FR-LIVE-1 学情辨析**：现场组织者按参赛者**编号**组织，系统抽取学生照片/姓名展示给参赛者，参赛者现场辨析作答；现场组织者可查看**参考答案**。

**FR-LIVE-2 案例分析（分组）**：现场组织者按**编号**组织，可进行**分组**、**抽题**、**展示题目**给对应参赛者/小组。

**FR-LIVE-3 谈心谈话**：现场组织者按**编号**组织，可**抽题**、**展示题目**给对应参赛者。

**FR-LIVE-4 学生素材管理**：系统维护学生库（姓名、照片、院系、学情信息），供学情辨析抽题使用；由业务管理人员维护（ADMIN 维护学生素材，ORGANIZER 仅使用）。

### 4.6 模块六：比赛练习（exam）

**FR-EXAM-1 练习模式**：辅导员参加练习批次，答题规则为**答一题、立即查看该题答案**。

**FR-EXAM-2 模拟模式**：辅导员参加模拟/学情辨析批次，答题规则为**全部答完一次性提交后，才能查看答案**。

**FR-EXAM-3 正式比赛笔试**：辅导员参加正式比赛的笔试环节，作答客观题 + 主观题；客观题提交后自动判分，主观题待人工评分。

**FR-EXAM-4 答题提交**：辅导员提交答案后，客观题立即判分，主观题进入「待评分」状态。

## 5. 业务规则汇总（权威清单）

| 编号 | 规则 |
| --- | --- |
| BR-QB-1 | 题目删除前置条件：未被任何试卷使用 且 不在共享题库。 |
| BR-QB-2 | 共享题库（及其中题目）对一切角色只读。 |
| BR-SCORE-1 | 基础知识成绩 = 客观分 + 主观分。 |
| BR-SCORE-2 | 客观题自动判分：单选/判断一致得满分否则 0；多选完全一致得满分否则 0。 |
| BR-SCORE-3 | 主观分人工评分，范围 [0, 该题分值]；未评分记 null（待评分）。 |
| BR-SCORE-4 | 阶段成绩 = 该环节题目得分之和。 |
| BR-SCORE-5 | 总成绩 = 各环节阶段成绩之和。 |
| BR-SCORE-6 | 排名按总成绩降序；同分按姓名拼音升序；并列名次连续编号。 |
| BR-SCORE-7 | 练习/模拟/学情辨析成绩不参与正式比赛排名。 |
| BR-COMP-1 | 比赛默认配置：笔试 2 环节 + 面试 3 环节。 |
| BR-EXAM-1 | 练习模式：答一题看一题答案。 |
| BR-EXAM-2 | 模拟模式：全部答完才能看答案。 |

## 6. 边界场景与异常处理

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| E-1 | 删除已被试卷引用的题目 | 拒绝删除，提示「题目已被试卷使用」 |
| E-2 | 删除共享题库中的题目 | 拒绝删除，提示「共享题库题目只读」 |
| E-3 | 随机抽题数量大于题库可用题目数 | 拒绝生成，提示可用数量不足 |
| E-4 | 非业务管理人员访问管理类接口 | 返回无权限（403） |
| E-5 | 辅导员查询他人成绩 | 拒绝，仅返回本人成绩 |
| E-6 | 院系学工负责人查询其他院系成绩 | 拒绝，仅返回本院系辅导员成绩 |
| E-7 | 主观分越界（小于 0 或大于题目分值） | 拒绝该行导入/评分，逐行反馈错误 |
| E-8 | 在批次时间范围之外作答 | 拒绝提交，提示不在有效时间内 |
| E-9 | 模拟模式中途提交 | 不允许中途提交；仅支持全部作答后提交 |
| E-10 | 未评分主观题参与成绩计算 | 不参与，成绩标记「待评分」 |
| E-11 | 比赛总成绩未完成（存在待评分环节） | 排名中该选手标记「待评分」，不计入最终排名，待全部评分后重算 |
| E-12 | 多选题部分选对 | 判 0 分（无部分分） |

## 7. 非功能需求（NFR）

| 编号 | 需求 |
| --- | --- |
| NFR-1 | 所有接口需做登录认证与角色鉴权。 |
| NFR-2 | 所有 SQL 必须参数化，禁止字符串拼接；禁止 DROP/TRUNCATE/无条件全表 DELETE。 |
| NFR-3 | 敏感信息（密码、JWT 密钥、数据库密码）不得硬编码，须环境变量/配置文件注入。 |
| NFR-4 | 密码必须加密存储（哈希），不得明文。 |
| NFR-5 | 成绩计算、权限范围、删除前置条件等核心规则必须收敛在业务 service 层，单一实现，无重复。 |
| NFR-6 | 对外成绩接口对手机号/身份证等敏感字段脱敏。 |
| NFR-7 | 分层架构遵循若依 MVC：controller → service → mapper → domain，依赖自上而下，禁止反向依赖。 |

## 8. 验收标准（AC）

> 每个功能模块的可验证验收标准，用于 specs/test-report.md 的执行。

### 8.1 题库管理

- AC-QB-1：ADMIN 能创建自建题库并增删改查题目；共享题库中的题目对 ADMIN 也表现为只读。
- AC-QB-2：删除「已被试卷引用」或「共享题库中」的题目时，操作被拒绝且提示准确。
- AC-QB-3：随机试卷能按指定题型/数量/分值生成，且生成后为题目快照（后续改题不影响已生成试卷）。

### 8.2 正式比赛

- AC-COMP-1：新建比赛默认生成 2 笔试环节 + 3 面试环节，且可增删改顺序。
- AC-COMP-2：比赛状态能按 未开始→进行中→已结束 流转。

### 8.3 日常练习 / 比赛练习

- AC-EXAM-1：练习模式答一题能立即查看该题答案。
- AC-EXAM-2：模拟模式在未全部作答时不能提交/不能看答案；全部提交后可看答案。
- AC-EXAM-3：正式比赛笔试客观题提交后立即自动判分。

### 8.4 成绩查询

- AC-SCORE-1：基础知识成绩 = 客观分 + 主观分 计算结果正确。
- AC-SCORE-2：阶段成绩、总成绩、排名计算正确（含同分并列）。
- AC-SCORE-3：权限范围正确：COUNSELOR 仅本人、DEPT_HEAD 仅本院系、ADMIN 全量。
- AC-SCORE-4：主观成绩导入成功更新对应主观分，越界行被拒绝并反馈。

### 8.5 现场比赛

- AC-LIVE-1：现场组织者可完成学情辨析抽学生、案例分析分组抽题展示、谈心谈话抽题展示。
